# EventIQ Server

Сервер публикации для [INVITO Studio v2, задача №29](https://github.com/akkunov/invito/issues/29). Работает отдельно от статического редактора и старых приглашений.

## Запуск

Требуется Node.js 24. Выполните `npm ci`, `npm run build` и `npm start`. Для локальной разработки используйте `npm run dev`.

- `STUDIO_DB` — путь к SQLite. Для сервера задайте каталог на постоянном диске с правами доступа только у процесса приложения. Поддерживается один сервер с локальным диском.
- `STUDIO_CREDENTIALS` — JSON-массив записей с полями `id`, `role` и `sha256`. Хешируйте независимый случайный токен длиной 32 байта и передавайте клиенту исходный токен по защищённому каналу. При пустом списке запросы авторов отклоняются. Для отзыва замените запись и перезапустите сервер.
- `MANAGER` читает и сохраняет собственные черновики и загружает медиа в свои проекты. `ADMIN` также имеет доступ к другим проектам, публикации и журналу аудита.

Для развёртывания используйте HTTPS. Храните резервные копии SQLite средствами SQLite и ограничивайте к ним доступ, поскольку RSVP содержит имя гостя.

## Публикация из текущего редактора

Экспортируйте полный пакет шаблона из Template Manager. Передайте токен через переменную `STUDIO_TOKEN` и выполните:

```sh
node scripts/import-template.mjs ./template.json https://studio.example.com --publish
```

Без `--publish` команда сохраняет черновик. Импорт использует идентификатор проекта из пакета, отправляет растровые файлы, сохраняет новую ревизию и при публикации выводит URL. Проект с медиа получает начальную ревизию для установления владельца. Незагруженные файлы блокируют публикацию этой ревизии. При повторном запуске загруженные изображения дедуплицируются.

Публичный URL работает как ссылка доступа к конкретной версии. Публикация следующей ревизии выдаёт новый URL. Доступ к публичной версии включает её изображения и разрешение отправить ответ на видимый RSVP этой версии. Лимит — до 30 новых ответов в минуту на опубликованную версию. Повтор с тем же ключом идемпотентности и тем же содержанием возвращает предыдущий результат. SVG и анимированные файлы отклоняются, растровые изображения проверяются и преобразуются в WebP. Локальные пути музыки `/audio/` требуют размещения файлов на том же сервере. HTTPS-аудио следует политике INVITO.

## API

Префикс `/api/studio-v2`. Маршруты проектов принимают заголовок `Authorization: Bearer <token>`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /projects/:id/draft` | Текущий черновик |
| `PUT /projects/:id/draft` | Документ Studio v2, ревизия 0 для нового проекта, актуальная ревизия для обновления |
| `POST /projects/:id/assets` | Байты PNG, JPEG или WebP с соответствующим Content-Type |
| `POST /projects/:id/publish` | JSON с `revision`, возвращает ID и публичный URL |
| `GET /projects/:id/audit` | Последние 100 событий записи |
| `GET /publications/:id/assets/:assetId` | Изображение из опубликованной версии |
| `POST /publications/:id/rsvp/:nodeId` | JSON `name`, `attendance`, `guests` и заголовок `Idempotency-Key` |

## Связь с INVITO

Схемы, рендерер и их зависимости скопированы из [INVITO на коммите 3104492](https://github.com/akkunov/invito/tree/3104492fd8d137b87c8307923302f59bb528ce94). При обновлении синхронизируйте эти файлы вместе, затем проверьте импорт, SSR и RSVP. Собственная реализация находится в `src/server`, `src/app/api` и `src/app/i`.

`npm run typecheck && npm run build && npm test` проверяет производственный сервер по HTTP и перезапускает его на той же базе. GitHub Actions запускает этот набор отдельно от Pages.
